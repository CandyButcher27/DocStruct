# datasets/

Everything needed to reconstruct the exact corpora behind the numbers in `paper/` —
and to prove the reconstruction is byte-identical to what was measured.

## Why the PDFs are not in this folder

They come to **3.2 GB**, and none of them are ours to redistribute:

| Corpus | Docs | Size | License | Redistributable by us? |
|---|---:|---:|---|---|
| OHR-Bench | 95 | 1.6 GB | per upstream release | No — fetch from source |
| PubMed Central | 133 | 544 MB | CC-BY (per-article, in manifest) | Yes in principle, but 544 MB |
| FinanceBench | 84 | 159 MB | CC-BY-NC-4.0 | Non-commercial only |
| arXiv (internal) | 68 | 859 MB | per-paper arXiv licenses | Mixed |

Mirroring 3.2 GB of third-party PDFs into git would be slow to clone, would duplicate
data that is already publicly hosted, and would put us in the position of
redistributing content under four different licenses — one of them non-commercial.

So this folder ships **the recipe and the proof**, not the bytes. Every corpus is
fetched by a script in `scripts/`, and `verify.py` then confirms what landed on disk
matches what the paper measured.

## Reconstruct

```bash
python scripts/fetch_ohrbench.py                 # 95 PDFs + 3,558 human Q&A
python scripts/fetch_pmc.py --per-journal 20     # 133 papers + publisher JATS XML
python scripts/fetch_financebench.py             # 84 SEC filings + 189 evidence rows
python scripts/fetch_dataset_v2.py               # 68 arXiv PDFs (ablations only)
```

Then verify:

```bash
python datasets/verify.py --all
```

```
arxiv          68/68 checksum-verified
financebench   84/84 checksum-verified
ohrbench       95/95 checksum-verified
pmc           133/133 checksum-verified
```

Non-zero exit on any missing file or checksum mismatch, so it works as a CI gate.

## What is here

```
manifests/     one row per document: filename, source URL, license, SHA-256
gold/          derived gold we generated, and may redistribute
verify.py      checksum verifier
```

### `manifests/`

| File | Corpus | Checksum width |
|---|---|---|
| `ohrbench_manifest.json` | OHR-Bench, 95 docs | 16-hex prefix |
| `pmc_manifest.json` | PMC, 133 papers (PDF + XML, DOI, journal, license) | full 64-hex |
| `financebench_manifest.json` | FinanceBench, 84 filings | full 64-hex |
| `dataset_manifest_v2.json` | arXiv, 68 PDFs | 16-hex prefix |

The checksum widths are inconsistent because the manifests were written at different
times. `verify.py` compares over whatever width each row records; a 16-hex prefix is
weaker than a full digest but still far past accidental collision.

### `gold/`

Only gold we generated ourselves and are free to redistribute:

- **`pmc_sections.json`** — section boundaries for 138 PMC papers, extracted from the
  publishers' JATS XML by `scripts/build_jats_gold.py`. Derived from CC-BY articles;
  per-article attribution is in `manifests/pmc_manifest.json`. This is the gold behind
  the section-boundary table in the paper.
- **`benchmark_qa_v6.json`** — 558 question/span pairs over the internal arXiv corpus,
  generated by an LLM. **Ablations only.** Our own rule is that gold generated from a
  tool's own output never carries a headline number, and this gold was generated from
  reference text rather than from any tool's chunks — but it is still synthetic, so it
  is used for measuring our configurations against each other and nothing else.

OHR-Bench and FinanceBench gold are deliberately **not** mirrored here. Both are
reconstructed exactly by their fetch scripts, and neither is ours to relicense.

## Reachability: read this before trusting any leaderboard on a new corpus

A gold answer that cannot be found in the PDF's own text cannot be scored against, by
any tool. That ceiling is identical for every tool, so it says whether a relevance
rule can measure the corpus at all:

```bash
python scripts/gold_reachability.py --gold data/qa/ohrbench.json --pdfs-dir data/ohrbench
python scripts/section_reachability.py
```

Measured ceilings: OHR-Bench **80.2%** span-reachable; PMC **84.7%** of body sections
locatable. Scores are read against those, never against 100%.

The script also warns about circularity, and the warning matters: once gold occupies a
large share of its page (FinanceBench: 69%), span and region reachability approach 100%
by construction and prove nothing.

## Corpus caveats worth knowing before you use one

- **FinanceBench is not a retrieval benchmark under a fixed-embedder protocol.** Its
  evidence is unreachable at top-5 under three different embedders on identical chunks —
  every tool scores MRR 0.0. That measures the retriever, not the chunker. See §6.4 of
  the paper.
- **OHR-Bench's ranking depends on the relevance rule**, and inverts between them on
  identical chunks. Never quote a single-mode number from it.
- **The internal arXiv corpus is incomplete on disk**: gold covers 92 documents, 68 PDFs
  are present. It is used for ablations, where that is tolerable, and for nothing else.
